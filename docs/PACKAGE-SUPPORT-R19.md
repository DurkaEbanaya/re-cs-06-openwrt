# r19: небольшой запас модулей и обычный opkg

**Кандидат в разработке. Не устанавливать пакеты r19 на ядро r18.** Опубликованные
образы и matching feed r18 не изменяются. Роутеры автоматически не обновляются.

Текущий ABI: `6.18.60-1-12f683381f3cdeed67e0cf206115e25b`. Подписанный
набор содержит 188 IPK, включая зависимости. Сборка прошла; аппаратная загрузка
r19, работа SQM и монтирование съёмных файловых систем пока не подтверждены.

Исходники matching пакетов публикуются отдельным архивом рядом с feed: patched
LEDE, feeds, закреплённые рецепты AWG, исходные загрузки и конфигурация. Локальный
radio overlay из этого публичного архива явно исключается флагом
`package-source.py --omit-radio-overlay`; это не комплект для воспроизведения
полного образа с закрытыми radio inputs. Старый строгий режим по умолчанию
по-прежнему отказывается упаковывать такой overlay случайно.

## Состав

В базовый образ добавлены `kmod-nf-socket` и `kmod-nft-socket`: дополнительные
выражения `socket transparent` для сторонних TPROXY-конфигураций. Правила HincyRay
от этого не меняются.

Отдельно (`=m`, не в образе) собираются:

- SQM: IFB, sched-core, CAKE, tc-full, sqm-scripts, luci-app-sqm и зависимости;
- ipvlan, dummy, br-netfilter, GRE/GRETAP, GRE6, VXLAN, IPIP, SIT;
- exFAT, VFAT, NTFS3 и кодировки cp437/ISO-8859-1/UTF-8.

WG/AWG, TUN/veth, NFQUEUE, USB/QMI/MBIM и исправления аппаратной поддержки r18
сохранены. Docker, новые VPN-серверы, автоматическое форматирование, extroot,
новый менеджер пакетов и автоматическое включение SQM не добавляются.
`kmod-br-netfilter` сохраняет штатные sysctl по умолчанию **0**: установка пакета
не должна сама включать прогон мостового трафика через iptables.

## Подписанный репозиторий

Вместо собственного сервера используется HTTPS-каталог файлов GitHub Release:
`Packages.gz`, `Packages.sig` и отдельные IPK. Доступный роутеру каталог должен
быть публичным: приватный GitHub Release без авторизации не подходит для opkg.
Публичный feed не должен содержать закрытые radio firmware, конфигурации роутеров
или приватный ключ подписи. Полный образ с радио остаётся отдельным личным файлом.

Адрес включает полную версию kernel package (в том числе ABI-хеш), а не `latest`.
`scripts/configure-release-feed.py BUILD HTTPS_URL` создаёт привязку к текущему
ядру и публичному ключу; затем образ надо пересобрать. При первом старте
`89-re-cs-06-package-sources` удаляет только прежнюю строку `recs06_release`,
проверяет ABI установленного kernel и наличие ключа, добавляет ровно один новый
источник. Остальные пользовательские источники не переписываются. Подписи
проверяет стандартный opkg; проверка сертификатов HTTPS остаётся включённой.

До выпуска надо проверить получение индекса и подписи именно по внешнему URL,
а не объявлять доступность по локальным файлам. После настройки обычный сценарий:

```sh
opkg update
opkg install luci-app-sqm
```

Пример означает **установить только нужную функцию**, не установить все IPK.
SQM на реальном интерфейсе включается и настраивается владельцем отдельно;
ускорение и задержки под нагрузкой требуют собственной проверки. Выбор tc-full
для зависимости `tc` сделан явно, без установки конкурирующих вариантов.

## Фиксация релиза

Ядро, его config и исходники модулей замораживаются вместе с matching пакетами.
Новая опция ядра или новый ABI — новый релиз, а не подмена старого feed. Уже
опубликованные r18 не получают переименованные r19 kmod или фиктивный пакет
kernel. `--force-depends`, отключение подписи и установка чужого kernel IPK
не являются способом совместимости.

Офлайн-проверки не заменяют реальную загрузку. Для стенда предусмотрены прежний
`test-network-support.sh` и новый опциональный `test-optional-support.sh`:
последний создаёт только собственный namespace, виртуальные интерфейсы, CAKE на
собственном IFB и hookless socket-expression. Он не включает SQM на LAN/WAN.
Необходимы отдельные согласованные обновление/резервные копии и окно проверки.
Холодный старт, реальные GRE/VXLAN-соединения и файловые системы на накопителях
нельзя объявлять проверенными по одному успешному созданию устройств/сборке.
