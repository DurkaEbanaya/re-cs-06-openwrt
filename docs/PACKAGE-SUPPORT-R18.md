# r18: база пакетов — лабораторная проверка, не массовый релиз

Исходная база и feeds закреплены в `sources.lock.json`. Добавочные рецепты AWG
и исходники ядрового модуля/утилит закреплены в `extra-packages.lock.json`.
Номер Linux сам по себе не подтверждает ABI-совместимость пакетов.

## Состав

- Kernel WireGuard, veth, TUN; wireguard-tools и LuCI WireGuard.
- Отдельный kernel AmneziaWG 3.1, matching tools и LuCI — не модули Keenetic.
- nft/NFQUEUE и userspace-зависимости для NFQ-программ.
- QMI/MBIM, serial option/Qualcomm, ACM, NCM/Huawei NCM, CDC Ethernet и RNDIS;
  uqmi/umbim, sms-tool, comgt, stty и usb-modeswitch.
- ModemManager, qmi-utils, mbim-utils, adb и luci-proto-modemmanager собираются
  отдельными IPK. ModemManager не установлен в базовом образе: обычное обновление
  не должно создавать второго владельца модема рядом с текущим QMI/netifd.

Zapret и 5gmodem не устанавливаются и не запускаются автоматически. Их postinst
может изменять сеть/firewall и выполнять автонастройку. Наличие зависимостей не
доказывает совместимость таких действий с HincyRay или другим VPN. Менеджер,
скачивающий AWG по стандартному номеру OpenWrt, по-прежнему не знает наш
`experimental-...` релиз. Использовать matching IPK, не подменять номер ОС.

## Подписанный автономный feed

После сборки:

```sh
python3 scripts/package-compatible-feed.py PATH_TO_LEDE NEW_OUTPUT_DIRECTORY
```

Скрипт проверяет транзитивные зависимости, архитектуру, точный kernel ABI,
отказывается от неоднозначных старых пакетов и подписывает `Packages` ключом
сборки. Выход: `Packages.gz`, `Packages.sig`, публичный ключ, manifest, SHA256SUMS
и IPK. Закрытый ключ не копируется. Kernel IPK не выдаётся: зависимость ядра должна
удовлетворяться уже установленной согласованной прошивкой, а не фиктивной заменой
пакета поверх старого ядра.

Это автономный feed, отдельно выдаваемый с matching полным образом в приватном
релизе, не общий официальный URL и не разрешение доверять ключу из
случайного архива. Сверять ключ/SHA256 независимым способом; не отключать подписи,
не применять force-depends/force-vermagic. Каталог можно обслуживать доверенным
локальным HTTP-сервером, но URL добавлять только после сверки ABI/ключа.
Не устанавливать разом все IPK: libc, сетевые службы и ModemManager требуют
отдельной оценки. Место оценивать по распакованным зависимостям в `/overlay`,
а не по большому свободному `/mnt/data`.

Новый `89-re-cs-06-package-sources` отключает official downloads.openwrt.org URL
даже при восстановлении network из backup, сохраняет custom feeds и подписи.
Внешний установщик может заново прописать чужие feeds; это не безопасный способ
получить совместимые пакеты.

## Разметки и безопасное обновление

Общий sysupgrade-образ рассчитан на **уже установленную нашу OpenWrt** на RE-CS-06
с основной парой p21/p23. Известные размеры root: 122 MiB (249856 секторов) и
2 GiB (4194304 секторов). Проверяются board, метки, размер kernel, отсутствие
перекрытия kernel/root и root PARTUUID из cmdline. Загрузочный слот не угадывается.

GPT, BOOTCONFIG, bootloader, secondary OS, ART/factory и data не переписываются.
Заводской GPT с неверной резервной копией не ремонтируется автоматически: для
этого обновления не требуется унификация дисков. Сток и активная secondary-пара
отклоняются: для них нужна отдельная проверенная установка, а не этот sysupgrade.
Один образ не означает универсальную первую установку для любых загрузчиков.

`re-cs-06-upgrade-preflight [IMAGE]` только читает состояние: ABI, packages,
mounts, место и preservation paths; с образом выполняет `sysupgrade -T`.
Это не backup и не разрешение на запись. Отчёт может содержать личные имена
путей: не публиковать его вслепую.

Важно: на r15/r16/r17 текущую запись выполняет **старый platform helper**.
Helper из нового образа не защищает запись, пока r18 ещё не загружен. Перед
первым обновлением нужны отдельная проверка старого helper/разметки, image check,
собственные backup и резервный доступ. Окно простоя и риск питания согласовать.

Config backup не равен backup установленного ПО. HincyRay/LuCI/модемные файлы,
mount-службы и состояние сохранить отдельно; проверить `/etc/sysupgrade.conf`.
Программы в p29 не форматируются. Образ не содержит чужие MAC/пароли/ключи/профили.
Public/external образ не содержит Qualcomm radio blobs; full-local вариант
сохраняет проверенный набор из отдельного workflow, без переноса калибровки.

## Границы проверки

Предохранители проверяются на обычных файлах, не на устройствах. До аппаратных
тестов нельзя утверждать, что WG/AWG handshake, NFQUEUE consumer, все USB-модемы
и сторонние установщики работают. Нужны: boot/config/identity, WG/AWG/veth в
отдельном netns без default route, NFQUEUE в собственной таблице, reload/stop,
USB ownership/reconnect. Для HincyRay отдельно — mark/DNS/fail-closed. Для двух
размеров root — место, config restore, reboot и данные. Компиляция не заменяет
эти проверки.

## Первая аппаратная проверка

На одном RE-CS-06 с primary root 249856 секторов выполнено согласованное
обновление r16 → full-local r18 после двух независимых проверенных копий backup.
Подтверждены readback ядра/rootfs, сохранность GPT/защищённых разделов/boot areas,
загрузочной среды, конфигурации и установленных дополнений. Профили и правила
HincyRay не изменялись. Модем QMI, обе точки доступа, Fluent/LuCI и подключение
ПК работают; большой раздел данных подключается автоматически.

В отдельных netns прошли veth, TUN и реальные WG/AWG handshake с передачей
пакетов. AWG проверен с параметрами по умолчанию, не с конфигурацией конкретного
провайдера. Отдельный временный NFQUEUE consumer получил и принял два ICMP-пакета
в собственном netns; рабочий firewall для этого не менялся.

Выявлена гонка первоначальной настройки PCIe-радио: netifd завершал попытку до
появления PHY. Добавлен `re-cs-06-radio-reconcile`: только на этой плате, только
для включённого radio с завершившейся ошибкой и уже найденным PHY, не более одной
попытки `wifi up RADIO` за ограниченное окно. Он не меняет настройки, не делает
`wifi down/reload` и не перезапускает сеть. После установки этой поправки повторная
перезагрузка подтвердила автоматический запуск обеих AP, модема и HincyRay.

Важно различать исходный образ r18 и установленную поверх него поправку радио:
первый прошитый образ её не содержал. Для следующей выдачи образ необходимо
пересобрать из актуальных исходников и заново зафиксировать его хеш. Для приватной
публикации пересборка с включённой поправкой выполнена и отдельно проверена офлайн;
новый хеш не объявляется повторно прошитым. Проверка
одного устройства и программного reboot не означает проверки cold boot,
root 4194304 секторов, других загрузчиков, всех модемов либо сторонних установщиков
Zapret/5gmodem. Эти установщики на рабочем роутере не запускались.
